Ask the AI, review the diff

The AI is a fast, literal junior. The diff is where you decide.

Why this chapter exists

In chapter 1 you made every edit yourself, so you know what a one-line change looks like. Today an assistant makes the edits, and your job changes from typing to judging.

Two words. The AI here is the assistant built into Cursor: you type a request in a panel, it proposes changes to your files. A diff is the list of what changed: lines removed (red, with a minus) and lines added (green, with a plus). The assistant is quick and confident and does exactly what your words say, which is not always what you meant. The diff is where you find out. Commits, pull requests and reviews are all about reading diffs; this is the first one.

A story

William's dev-setup repo, ladder.md, 2026-08-22

William keeps a file about the order to make a project safe. One paragraph is about files copied from a template: a README about someone else's project, a check that installs things and calls that a test. His line: "A green check mark that verified nothing is actively misleading; you will trust it exactly when you shouldn't." An AI's explanation of its own change is the same kind of thing. It sounds like something was checked. It was not. The diff is the only part that is a fact.

What you will do

  • Confirm the assistant read the rules for this repo.
  • Ask for a small change, read the diff, accept it.
  • Ask for a vague change, watch, reject it.
  • Ask a question that should change nothing.
  • Ask for a note page and count the files it touched.
  • Mark this chapter done by asking, and check the diff is one attribute.

Do it

  1. Open the folder and read the rules. In PowerShell 7: 
    cursor ~\dev\workbook
    Open AGENTS.md and read its ten rules once. Cursor reads this file on its own; it is the contract between you and the assistant. Then open Cursor Settings (Ctrl+Shift+J) and find Rules: the project rules should list workbook.mdc, always applied. That is .cursor/rules/workbook.mdc, four lines pointing at AGENTS.md. If it is not listed, first gotcha.
  2. Open the AI panel. Ctrl+L. At the bottom of the message box is a mode switch: Agent can edit files, Ask can only answer. Choose Agent and type: 
    Which rules apply to this repo? List them by number. Do not change anything.

    The ten rules from AGENTS.md, in order, and no file changed. If it says it has no rules, first gotcha.

  3. A small, clear ask. 
    In index.html, add one short paragraph directly under the title saying who this workbook is for. Nothing else.

    First one sentence saying what it will do (rule 1, line 7 of AGENTS.md). Then index.html in the panel with a green block of one to three lines. Count the red lines: none, because you asked it to add, not remove. Read the green ones. Click Accept. Save if the tab shows a dot, refresh the browser.

    If you would have said it differently, change the words yourself now. The assistant drafts; you decide.
  4. A vague ask. 
    Make the site look modern.
    Watch, and click nothing yet.

    A lot. styles.css with many red and green lines, probably new colours written as # codes (rule 8 forbids them), maybe index.html too. Before you touch a button, write down or screenshot (Win+Shift+S) which files it touched and one change you did not ask for. You need this twice today.

    Now Reject (or Reject all). Refresh: the site is as it was. You asked for a feeling; it guessed. Every guess was a decision you did not make, and there were dozens in one click.
  5. A question that should change nothing. Switch to Ask: 
    Explain the CSS rule in styles.css that makes the counter under the chapter list work.

    An explanation, no Accept or Reject, no file changed. It should mention counter-increment: done on .chapters li[data-status="done"] and .progress::after with counter(done) " of 12 done".

    Check it: open styles.css, search counter(done), read the two rules. If explanation and file disagree, the file is right.
  6. A task that touches exactly two files. Back to Agent: 
    Create a new note page called "What a diff is". Follow rule 4.

    Two files, no more: a new notes/2026-MM-DD-what-a-diff-is.html copied from notes/_template.html, and one line in notes/index.html under Pages (there is a commented-out example on line 39; it may simply use that). A third file: Reject, ask why.

    Accept. Open the new page and write it yourself: under What I learned, what you noted in step 4. Save.

Check

index.html has your paragraph under the title and nothing else looks different. styles.css is as chapter 1 left it: no dot on its tab, no change marks in the scrollbar. The Notes page lists your new note under Pages and it opens with the right title. Your note from step 4 exists. Counter still says 2 of 12 done; that changes below.

What can go wrong

  • It says it has no rules, or skips the one-sentence explanation. Cursor did not load AGENTS.md, usually because you opened a parent folder; rules are per folder. Close Cursor, run cursor ~\dev\workbook, check Settings → Rules again.
  • It wants to run npm install or add an extension. Rule 5 (line 20) says ask first. Say no. Nothing in this chapter installs anything.
  • "You've hit your limit". Cursor's free plan caps requests per month. Tab completions and small asks are cheap; this chapter uses about eight. Tell William if you run out.
  • A one-line ask produced hundreds of changed lines. It "tidied" the whole file's indentation or line endings. Reject. A diff should be the size of the ask; format-on-save is off in .vscode/settings.json for this reason.
  • It apologises and does the same thing again. Rephrase: name the file, the line, and what not to touch. "Sorry" is not a diff.
  • The change is in the file before you clicked anything. Some Cursor versions write first and offer Reject after; Reject still undoes it. If lost, Ctrl+Z, and from chapter 3 git diff shows every change no matter who made it.

Mark it done

  1. In Agent mode: 
    Mark chapter 2 done.

    One sentence, then index.html with one red line and one green line, differing only in todo becoming done on the data-chapter="02" line. Rule 3.

  2. If it touched anything else, another file, another line, something it "also fixed", Reject and say why: 
    That also changed [what it changed]. Rule 3 says one attribute. Try again.
  3. Accept. Save. Refresh.

    Filled box next to chapter 2. Counter says 3 of 12 done.

  4. One line in Today I learned, at the top. You may ask the assistant to add it (rule 4 allows the top of til.html), but type the sentence into the ask word for word. It is yours.

Pair with William

You will: show the note page from step 6 and read out what the "modern" ask changed that you did not ask for. Then say the rule for the rest of the course: review the diff, not the explanation. The explanation is what it says it did; the diff is what it did.

William will: ask "what did it change that you did not ask for?" until the answer is specific. Then he asks the assistant to mark a Library item seen, rejects the diff in front of you, and opens the terminal for git status again. The list is longer than last time.

Deliberately not in this chapter

No agent running ten steps on its own. No "fix everything" prompts. No other AI tools. One ask, one diff, one decision, and every decision is yours. The terminal stays closed except when William opens it; chapter 3 gives you git diff, the same red and green without asking anyone.
