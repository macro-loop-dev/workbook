Edit the file, refresh the browser

The file is the website. There is nothing in between.

Why this chapter exists

Most people meet websites as something that happens on a server far away. This one is a folder on your laptop, and the browser is just a program that draws files from it. Once that is true in your hands, every later chapter is a variation: the same file, changed a more careful way, drawn somewhere further away.

A story

FloatNote, August 2026

FloatNote has a docs page that promises "every example below runs through the real calculator, live". Someone added examples about cryptocurrency to the file. The page did not load crypto prices. So the examples sat there blank, and the page was lying. The file said one thing; the screen said another. Everything in this workbook is about keeping those two the same, and today they are one refresh apart.

What you will do

  • Change text and see it change.
  • Change a colour and see it change everywhere.
  • Break the page on purpose and see how the browser copes.
  • Mark this chapter done by hand.

Do it

  1. Open the folder in Cursor. In PowerShell 7: 
    cursor ~\dev\workbook
    The left side lists the files. Click index.html.
  2. Open the same file in a browser. Open File Explorer, go to C:\Users\<you>\dev\workbook, double-click index.html. Put the browser and Cursor side by side. The address bar starts with file:///: the browser is reading your disk.
  3. Change some text. In Cursor, find the line that starts <p class="lede">. Change any word. Press Ctrl+S. In the browser press F5.

    Your word is on the page. If not: did you save? The dot on the tab means unsaved.

  4. Change a colour. Open styles.css. Near the top, find --accent: #2733c9;. Change it to --accent: #c0392b;. Save, refresh.

    Every link and every step number changed at once. One line controls all of them; that is what the :root block is for. Put it back.

  5. Break it. Back in index.html, find <h1>The Workbook</h1>. Delete the > after h1 so it reads <h1The Workbook</h1>. Save, refresh.

    The title is probably gone or the page looks odd, but the browser did not crash and the rest is still there. Browsers forgive HTML; they will not forgive JavaScript in chapter 7. Put the > back.

  6. Look at the list. Find the line that starts <li data-chapter="01". Read it slowly. data-status="todo" is a label on that item. Now open styles.css and search for data-status. Those three CSS rules are the entire progress system: an item labelled done gets a filled box, and the counter counts them.

Check

With the browser open on index.html: the counter under the list says 1 of 12 done (chapter 0, which William marked). The lede says your word. The accent colour is blue again.

What can go wrong

  • Refresh changes nothing. Not saved (the tab shows a dot), or the browser is showing a different copy of the file. Check the address bar contains dev/workbook, not Downloads.
  • You edited the wrong chapter's line. The data-chapter number is on the same line as the attribute. Undo with Ctrl+Z.
  • Cursor offers to complete what you type. That is Tab completion. Press Esc to ignore it this chapter; chapter 2 is where you start using it.
  • The page has no styling at all. The <link rel="stylesheet"> line near the top was changed or styles.css was moved. Undo.

Mark it done

  1. In index.html, on the data-chapter="01" line, change data-status="todo" to data-status="done".
  2. Save. Refresh.

    Filled box next to chapter 1. Counter says 2 of 12 done.

  3. Open the Library in Cursor (library/index.html). Pick one item you have actually looked at. Change its data-seen="no" to "yes". Save, refresh that page: the new badge is gone and the count dropped by one.
  4. Make your first note: copy notes/_template.html to notes/2026-MM-DD-the-file-is-the-site.html (right-click the file in Cursor, Copy, Paste, rename). Fill in the three headings, even one line each. Add a line for it under Pages in notes/index.html; there is a commented-out example to copy.
  5. One line in Today I learned, at the top.
