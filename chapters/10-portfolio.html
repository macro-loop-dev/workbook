Restructure into a portfolio

Move everything one folder down without breaking a single link, then put your name on the front door.

Why this chapter exists

The workbook was never meant to be the whole site. It is one project, the first one, and the site should outlive it. Today the home page becomes yours, the workbook moves to /workbook/, and the repo gets your domain as its name.

The skill is not the new page. It is moving code that already works, proving nothing broke, and leaving a forwarding address for every old link. Real projects do this constantly and it goes wrong constantly, because a move looks harmless and touches everything.

A story

William's dev-setup repo, August 2026

William renamed a whole repository: the rollout registry became macro-loop/rung. GitHub forwards the old name, so nothing seemed to need changing. He checked every pointer anyway: the clone on each machine, a skill that cited the old path, a doc that linked it. Two were stale. Nothing broke silently, because he assumed something would. That assumption is the whole of this chapter.

What you will do

  • Move the workbook pages and their script under workbook/.
  • Fix every path the move broke, with search and replace, not by hand.
  • Watch a test fail because of the move, then fix the test.
  • Add a redirect so old chapter links still work.
  • Write the new home page, in your own words.
  • Rename the repo to your domain.

Do it

  1. Start green. Terminal in ~\dev\workbook: 
    git switch main; git pull; git switch -c chapter-10; npm test

    Every suite passes. If it does not, fix that first; a move on top of a failing test hides which change broke what.

  2. Move the files with git, not Explorer. git mv records a rename; dragging in Explorer looks to git like a delete and a new file, and the history of the page is lost. 
    New-Item -ItemType Directory workbook, src\workbook | Out-Null
git mv index.html workbook\index.html
git mv chapters workbook\chapters
git mv src\main.ts src\workbook\main.ts
git status

    Fourteen lines of renamed:, in green.

  3. Fix the imports in the moved script. Open src/workbook/main.ts. It is one folder deeper now, so every import of a sibling needs one more ... Change from "./progress" to from "../progress", and the same for ./chapters and ./library. Then find where a chapter link is built (search for chapters/) and make it /workbook/chapters/: root-relative, starting with a slash, because the page and the chapters are no longer in the same folder.
  4. Fix the paths in the moved pages with one search. Cursor: Ctrl+Shift+H opens Replace in Files. Do these four, in this order, and click the replace-all icon each time. Read the file list before each one: every hit should be under workbook/.
    FindReplace with
    href="../styles.css"href="/styles.css"
    href="../library/index.html"href="/library/index.html"
    href="../notes/index.html"href="/notes/index.html"
    href="../index.html"href="/workbook/index.html"
    Then in workbook/index.html and library/index.html, change the script line to <script type="module" src="/src/workbook/main.ts"></script>, and in every page's nav change the brand link href="/workbook/index.html" on the first <a> back to href="/" with your name as its text. The Chapters link stays pointing at /workbook/index.html.

    Root-relative paths only work when a server is involved, which since chapter 8 is always. This is the day file:// would have stopped working anyway.

  5. Tell Vite where the pages went. In vite.config.ts, replace the block that builds pages with: 
    const pages: Record<string, string> = {
  index: "index.html",
  workbook: "workbook/index.html",
  library: "library/index.html",
};
for (const f of readdirSync("workbook/chapters")) {
  if (f.endsWith(".html")) pages[f.slice(0, -5)] = `workbook/chapters/${f}`;
}
    In the notes plugin's page() template, the nav's Chapters link becomes /workbook/index.html and the brand link becomes / with your name.
  6. Leave a forwarding address. Cloudflare Pages reads a file called _redirects from the root of what it serves. Vite copies anything in public/ to that root untouched. 
    New-Item -ItemType Directory public | Out-Null
Set-Content -Path public\_redirects -Value "/chapters/* /workbook/chapters/:splat 301"

    One line. :splat means "whatever came after"; 301 means "moved permanently", which browsers and search engines remember.

  7. Run the tests and read the failure. 
    npm test

    chapters.test.ts fails: it cannot find the chapters folder, because you moved it. This is the test doing its job. A test that still passed after you moved the thing it checks would be checking nothing.

  8. Fix the test. In src/chapters.test.ts, the directory line and the link check change: 
    -const dir = join(import.meta.dirname, "..", "chapters");
+const root = join(import.meta.dirname, "..");
+const dir = join(root, "workbook", "chapters");
 ...
-    ok(`${f} links to ${m[1]}`, existsSync(join(dir, m[1])));
+    // A link starting with / is from the site root; anything else is from
+    // the chapter's own folder.
+    const target = m[1].startsWith("/") ? join(root, m[1]) : join(dir, m[1]);
+    ok(`${f} links to ${m[1]}`, existsSync(target));
    npm test; npm run build

    All green, and dist\workbook\chapters holds twelve files: (Get-ChildItem dist\workbook\chapters).Count prints 12. dist\_redirects exists.

</html>

    The GitHub link changes in step 12. Everything on this page uses classes that already exist in styles.css; a new look is a later project, not this chapter.

  10. Click through everything. 
    npm run dev
    Open http://localhost:5173/. Home, Workbook, one chapter, its prev and next, Library, Notes, one note, and back to home from each nav. Then the same on npm run dev:full and tick a chapter: the checkbox still saves, because /api/progress never moved.
  11. Commit in slices, then the PR. One idea per commit; a reviewer can read four small diffs and cannot read one big one. 
    git add workbook src vite.config.ts library; git commit -m "refactor: move the workbook under /workbook/"
git add src/chapters.test.ts; git commit -m "fix: chapters test reads the new folder"
git add public; git commit -m "chore: redirect old chapter links"
git add index.html; git commit -m "feat: home page"
git push -u origin chapter-10; gh pr create --fill

    CI green. William reviews. After the merge, open your domain on your phone: the home page, then an old chapter link such as /chapters/01-edit-and-refresh.html, which should land on the new path.

  12. Rename the repo. After the merge, from inside the repo, with your domain as the new name (dots are allowed): 
    git switch main; git pull
gh repo rename your-domain.example
git remote set-url origin https://github.com/macro-loop-dev/your-domain.example.git
git remote -v
    GitHub forwards the old name, so the Cloudflare connection and William's clone keep working. Set the URL anyway: forwarding is a courtesy, not a promise. Then change the GitHub link on your home page to the new name, and rewrite README.md so it is about your site, not the course. Keep the "Deliberately absent" section; it is the most useful part. Commit both as docs: the readme is mine now, on a branch, through a PR, like everything.

Check

On the live site: / is your page; /workbook/ is the workbook with the counter; an old /chapters/... link forwards; a tick on a chapter survives a refresh on your phone. npm test and npm run build are green. git remote -v shows the new name. gh repo view shows your README.

What can go wrong

  • A chapter page loads with no styling. Its stylesheet link is still ../styles.css, which now points one folder too high. Step 4 missed it; search again for ../styles.css.
  • Old links give a Cloudflare 404 for a minute after the merge. The redirect file deploys with the build; wait for the deployment to say Success, then hard-refresh.
  • _redirects is missing from dist. It is not in public/, or the folder is named differently. Vite only copies from a folder called exactly public at the root.
  • The chapters test passes before you fixed it. Then it is not reading the folder you moved; check the path in the test is the one you think.
  • git push says the repository was not found after the rename. The remote URL is still the old name and forwarding has not caught up, or you typed the new name differently in set-url. git remote -v and compare with gh repo view --json nameWithOwner.
  • The AI offers to "clean up" the move by rewriting files. Reject. A move should be a move; a rewrite in the same PR hides whether the move worked.

Mark it done

  1. Tick chapter 10 on the live site, at its new address. The database does not know the page moved; that is what the split in chapter 9 bought.
  2. One line in your Today I learned page, which is now written in Markdown and lives at /notes/til.html on the live site.

Pair with William

You will: give a tour of the live site from your phone, then show the four commits and say why they are four.

William will: relax the branch protection to "pull request required, no approval required", so from now on you can ship alone and he reviews when asked. Then he runs his repo audit on your repo, at the "internal" tier, and you read the report together. Whatever it flags is your backlog, not his; put it in a note.

Deliberately not in this chapter

No transfer of the repo to your own GitHub account. It is possible, it is optional, and it breaks the Cloudflare git connection, so it is done last or not at all; William has the steps. No new design: the home page uses the workbook's tokens on purpose, and changing the look is a project of its own, with its own PRs. No analytics, no contact form.
