Commit in the terminal

git is a save button with a memory and a reason field.

Why this chapter exists

Ctrl+S saves the file and forgets what it looked like before. git keeps every version you tell it to keep, each with a sentence about why, and shows the difference between any two. From today, nothing you commit is lost.

Four words. A repository (repo) is your folder plus its history, kept in a hidden folder called .git. A commit is one saved version with a message. Staging is choosing which files go into the next commit: a box you fill before sealing it. A hook is a small program git runs at a fixed moment, such as just before a commit. You do all of it in the terminal, because the terminal shows every step.

A story

William's dev-setup repo, ladder.md, 2026-08-22

William's list of what to do first on any project has one rung at the top: make sure a copy exists somewhere else. His note under it: "The dangerous case isn't a sloppy project; it's a good one. Thorough documentation, a careful test plan, months of considered decisions, about to go live, and no git remote because on day one you were just trying something." At the end of this chapter you will have four commits, and they will exist on exactly one laptop. That is the situation his note is about. Chapter 4 fixes it. Today, know that it is true.

What you will do

  • See what git thinks has changed since you cloned.
  • Commit the work from chapters 0 to 2, in two commits with real messages.
  • Turn on the secret scanner, try to commit a fake key, get refused.
  • Mark this chapter done with one commit of one line.

Do it

  1. Open the terminal inside Cursor. Ctrl+` (the key under Esc). Check which shell and which folder: 
    $PSVersionTable.PSVersion
Get-Location

    A version starting with 7, and C:\Users\<you>\dev\workbook. If not: Set-Location ~\dev\workbook. Everything below is typed here.

  2. What changed since you cloned? 
    git status

    Something like:

    On branch main
Your branch is up to date with 'origin/main'.

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
        modified:   index.html
        modified:   library/index.html
        modified:   notes/index.html
        modified:   notes/til.html

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        notes/2026-MM-DD-the-file-is-the-site.html
        notes/2026-MM-DD-what-a-diff-is.html

no changes added to commit (use "git add" and/or "git commit -a")
    Modified: git knows the file and it differs from the last commit. Untracked: git has never seen it. origin/main is GitHub's copy; "up to date" is about commits only, and you have made none.
  3. Read the diff. 
    git diff index.html

    Header lines, then blocks starting @@. Lines with - are red, the old version; + green, the new. You will recognise the three data-status lines and the chapter 2 paragraph. Same colours as Cursor's panel, nobody's opinion in between. If a : sits at the bottom of the screen, press q.

  4. Stage the file. 
    git add index.html; git status

    index.html moved up to "Changes to be committed", green. It is in the box. Nothing is saved yet.

  5. Commit it. 
    git commit -m "docs: mark chapters 0 to 2 done and say who this is for"

    [main 3c9a1d4] docs: mark chapters 0 to 2 done and say who this is for then 1 file changed, 4 insertions(+), 3 deletions(-); your numbers may differ by one. 3c9a1d4 is the commit's id, the first seven characters of a long code; nobody types them.

    The message starts with docs:. This repo and FloatNote use three prefixes: feat: a new thing, fix: something wrong is now right, docs: text, pages and notes, which is everything here for now. Colon, space, one short sentence.
  6. Commit the notes and the Library change. Naming a folder stages everything inside it, new files included. 
    git add notes library; git commit -m "docs: first notes and one library item seen"

    5 files changed, and two lines starting create mode 100644 notes/2026-: the new pages.

  7. Look at the history. 
    git log --oneline

    Newest first. Your two on top, the first marked (HEAD -> main). Below, the commits that were there when you cloned; the top of those is marked (origin/main, origin/HEAD). HEAD is where you are; origin/main is where GitHub's copy is. Two commits apart, and GitHub does not know.

  8. Turn on the hook. Open .githooks/pre-commit in Cursor: four lines, the last runs gitleaks, which scans for anything shaped like a password or key. Cloning does not switch hooks on. This does, for this folder only: 
    git config core.hooksPath .githooks; git config core.hooksPath; gitleaks version

    .githooks, then a version starting with 8.

  9. Plant a fake key. gitleaks looks for shapes. A real GitHub token is ghp_ plus 36 letters and digits. This one is made up: never issued to anyone, opens nothing. It is written in two halves joined with + because this chapter lives in the same repo, and the scanner would refuse this very page if it were whole. 
    Set-Content -Path scratch.txt -Value ('github_token = "ghp_' + 'cI3qS7xOX7ZRdDOU7RcflxMNwhusuWJnVDQv' + '"')
Get-Content scratch.txt

    One line, the halves joined into one token.

  10. Try to commit it. 
    git add scratch.txt; git commit -m "test: try to commit a fake key"

    A small gitleaks logo, then:

    Finding:     github_token = "REDACTED"
Secret:      REDACTED
RuleID:      github-pat
Entropy:     4.853056
File:        scratch.txt
Line:        1
Fingerprint: scratch.txt:github-pat:1

9:43PM INF 0 commits scanned.
9:43PM INF scanned ~58 bytes (58 bytes) in 240ms
9:43PM WRN leaks found: 1

    No [main ...] line: the commit did not happen, and git log --oneline shows nothing new. Notice REDACTED: the hook will not even print what it found.

    git has a flag that skips hooks. You are not going to learn it, and chapter 4 runs this same scan on GitHub's computers for the people who do.
  11. Clean up. Out of the box, then delete. 
    git restore --staged scratch.txt; Remove-Item scratch.txt; git status

    nothing to commit, working tree clean.

Check

git log --oneline shows two commits of yours above the one marked origin/main. git config core.hooksPath prints .githooks. git status is clean. Test-Path scratch.txt prints False.

What can go wrong

  • The fake key committed with no gitleaks lines. The hook is not on in this folder: you ran step 8 somewhere else. Check Get-Location, redo step 8 inside ~\dev\workbook, then undo that commit but keep the file, git reset --soft HEAD~1, and do step 11.
  • .githooks/pre-commit: line 4: gitleaks: command not found. The hook runs in git's own small shell, which finds programs the same way your terminal does. Make sure gitleaks version works in PowerShell first (chapter 0's first gotcha). If it does and the hook still fails, close Cursor completely and reopen: its terminal inherits the program list from the moment Cursor started.
  • "LF will be replaced by CRLF", or the reverse. Windows has historically ended lines with two invisible characters; everything else uses one. .gitattributes says this repo uses one, and the warning means git will convert. Harmless.
  • Wrong name or email on the commit. git log -1 shows the author. Fix the setting, then the last commit: git config --global user.email "you@example.com"; git commit --amend --reset-author --no-edit.
  • A screen full of ~ and no prompt. You forgot -m and git opened an editor called vim. Esc, type :q!, Enter. Always use -m.
  • Cursor's Source Control panel offers a tick and a number. Same git, with add and the hook output hidden. This chapter and the next: terminal only.

Mark it done

  1. Change data-status on the data-chapter="03" line of index.html to done. By hand or by asking: your choice from now on.
  2. Look before you commit: 
    git diff

    Exactly one - line and one + line. More means something else changed; find out what first.

  3. Commit, through the hook this time: 
    git add index.html; git commit -m "docs: mark chapter 3 done"

    The logo, no leaks found, then [main ...] docs: mark chapter 3 done and 1 file changed, 1 insertion(+), 1 deletion(-).

  4. One line in Today I learned, at the top. Commit that too, so nothing is left hanging: 
    git add notes/til.html; git commit -m "docs: til for chapter 3"; git status

    Working tree clean. Refresh the browser: 4 of 12 done.

  5. Say it out loud: four commits, one laptop.

Deliberately not in this chapter

No push. No branches. No git commit -a, no Source Control panel, no undo beyond the one in the gotchas. Nothing today leaves the laptop. That is the whole discomfort of this chapter, and chapter 4 is the fix.
