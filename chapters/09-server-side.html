Save progress on the server

One truth, kept where every browser can reach it. A secret that never touches a file in the repo. Two tables of SQL. The smallest amount of each that does the job.

Why this chapter exists

Chapter 7 left you with two truths: the tick in your laptop's browser and the tick on your phone disagree, because each browser remembers for itself. The fix is to stop letting browsers remember and put the answer in one place they all ask. That place is a server: a program on someone else's computer that waits for requests and answers them. Your site has been served from Cloudflare since chapter 5, but so far it only handed out files. Today it starts running code you wrote.

Three new things, each in its smallest form. A database is a program that keeps tables and lets you ask questions about them in a language called SQL; ours is Cloudflare's D1, and it has two tables. An API is a set of URLs meant for programs rather than people: your page will ask /api/progress for the ticks and send a PUT request to change one. And a secret: anyone can read the scoreboard, but only someone holding the key can change it, and the key lives in exactly one place that is not this repo.

The code that runs on the server is a Pages Function: a TypeScript file in a folder called functions, where the file's path is the URL it answers. It deploys with the site, from the same pull request, so the workflow you already know does not change. The tool that talks to Cloudflare from your terminal is called wrangler.

A story

William's dev-setup repo, CLAUDE.md, August 2026

William runs a small search server on a machine at home. It needs a key in a header, and it answers {"error":"unauthorized"} without one. His notes carry a rule in bold: that error is almost never the server. The key sits in an environment variable, and a program only sees the variables that existed when it was started. A terminal opened before the key was set has an empty one, and every program it launches inherits the emptiness. So the checklist reads: a healthy /health plus an unauthorized /search is a stale process, not an outage; check the length of the variable before blaming the network. Diagnosing a 401 is a skill. By the end of this chapter you will have made every kind of 401 there is, on purpose, and know which part of the chain each one points at.

What you will do

  • Install wrangler, log in, and create a database called workbook.
  • Write a migration: the SQL that creates the two tables. Run it against a local copy, then against the real one.
  • Type one UPDATE by hand to mark chapters 0 to 8 done. It is the last time progress changes by hand.
  • Write three Functions: read the scoreboard, change one chapter, mark a Library item seen. The second and third check a key.
  • Change main.ts to ask the server instead of remembering.
  • Run the whole thing on your laptop with a local database, then ship it, then tick chapter 9 on the live site and see it on your phone.

  8. Create functions/api/progress.ts. The first Function. Its path is its URL: functions/api/progress.ts answers /api/progress. onRequestGet runs for a GET, which is what a browser sends when it just wants to read. 
    // GET /api/progress
// -> { "chapters": { "00": "done", ... }, "seen": ["floatnote", ...] }
// Reading needs no key: the site is public, so the scoreboard is too.

interface Env {
  DB: D1Database;
}

export const onRequestGet: PagesFunction<Env> = async ({ env }) => {
  const progress = await env.DB.prepare(
    "SELECT chapter, status FROM progress ORDER BY chapter",
  ).all<{ chapter: string; status: string }>();
  const chapters: Record<string, string> = {};
  for (const row of progress.results) chapters[row.chapter] = row.status;

  const seen = await env.DB.prepare("SELECT item_id FROM seen").all<{ item_id: string }>();
  return Response.json({ chapters, seen: seen.results.map((row) => row.item_id) });
};

    env.DB is the binding from wrangler.toml. prepare holds a SQL sentence, all runs it and returns rows. There is no key check here on purpose: the site is public, so the scoreboard is too.

  9. Create functions/api/progress/[chapter].ts. Square brackets in the file name mean "whatever came here in the URL": /api/progress/09 arrives with params.chapter equal to "09". This one answers PUT, which is what the page sends to change something, and it checks the key first. 
    // PUT /api/progress/08   header X-Workbook-Key: <the key>   body {"status":"done"}
// -> { "chapter": "08", "status": "done", "updated_at": "2026-..." }
// The file name is the route: [chapter] means "whatever came after /progress/".
import { isChapterId, isStatus } from "../../../src/progress";

interface Env {
  DB: D1Database;
  WORKBOOK_KEY?: string;
}

export const onRequestPut: PagesFunction<Env, "chapter"> = async ({ request, env, params }) => {
  // The secret comes from the environment, never from a file in the repo.
  if (!env.WORKBOOK_KEY) {
    return Response.json({ error: "WORKBOOK_KEY is not set on the server" }, { status: 500 });
  }
  if (request.headers.get("X-Workbook-Key") !== env.WORKBOOK_KEY) {
    return Response.json({ error: "unauthorized" }, { status: 401 });
  }

  const chapter = params.chapter;
  if (!isChapterId(chapter)) {
    return Response.json({ error: "no such chapter" }, { status: 404 });
  }
  const body = (await request.json().catch(() => null)) as { status?: unknown } | null;
  const status = body?.status;
  if (!isStatus(status)) {
    return Response.json({ error: 'status must be "todo" or "done"' }, { status: 400 });
  }

  const updatedAt = new Date().toISOString();
  await env.DB.prepare("UPDATE progress SET status = ?1, updated_at = ?2 WHERE chapter = ?3")
    .bind(status, updatedAt, chapter)
    .run();
  return Response.json({ chapter, status, updated_at: updatedAt });
};

    Three things to notice. The key comes from env.WORKBOOK_KEY, which Cloudflare fills in from a secret William sets in the dashboard, and from .dev.vars on your laptop; no file in the repo ever contains it. A wrong key is 401; that number means "who are you?", while 403 would mean "I know who you are and the answer is no". And isChapterId and isStatus are imported from src/progress.ts, the same file the page uses: one vocabulary, checked on both sides.

  10. Create functions/api/seen/[id].ts. The same shape for Library items. 
    // PUT /api/seen/floatnote   header X-Workbook-Key: <the key>   body {"seen":true}
// -> { "item_id": "floatnote", "seen": true }
// true adds a row, false removes it; the table only lists what you have seen.

interface Env {
  DB: D1Database;
  WORKBOOK_KEY?: string;
}

export const onRequestPut: PagesFunction<Env, "id"> = async ({ request, env, params }) => {
  if (!env.WORKBOOK_KEY) {
    return Response.json({ error: "WORKBOOK_KEY is not set on the server" }, { status: 500 });
  }
  if (request.headers.get("X-Workbook-Key") !== env.WORKBOOK_KEY) {
    return Response.json({ error: "unauthorized" }, { status: 401 });
  }

  const id = params.id;
  if (typeof id !== "string" || !/^[a-z0-9-]{1,64}$/.test(id)) {
    return Response.json({ error: "bad item id" }, { status: 400 });
  }
  const body = (await request.json().catch(() => null)) as { seen?: unknown } | null;
  if (typeof body?.seen !== "boolean") {
    return Response.json({ error: "seen must be true or false" }, { status: 400 });
  }

  if (body.seen) {
    await env.DB.prepare("INSERT OR REPLACE INTO seen (item_id, seen_at) VALUES (?1, ?2)")
      .bind(id, new Date().toISOString())
      .run();
  } else {
    await env.DB.prepare("DELETE FROM seen WHERE item_id = ?1").bind(id).run();
  }
  return Response.json({ item_id: id, seen: body.seen });
};

  15. Replace src/main.ts. The page stops remembering. On load it asks /api/progress; when you tick, it sends a PUT with the key in a header; the key is the one thing kept in this browser, asked for once and cleared if the server ever says 401. 
    // The page's only script. Draws the chapter list and the Library from the
// files in src/, then asks the server which chapters are done and which
// items are seen. This browser remembers one thing: the key that lets you
// write. Everything else is on the server, so every browser agrees.
import { CHAPTERS, chapterId } from "./chapters";
import { isCategory } from "./library";
import libraryData from "./library.json";
import { CHAPTER_IDS, countDone, isStatus, type Status } from "./progress";

const KEY_KEY = "workbook.key";

interface ServerState {
  chapters: Record<string, Status>;
  seen: string[];
}

// GET /api/progress. Null when there is no server (plain npm run dev), so
// the page still draws; every box just shows todo and nothing sticks.
async function loadState(): Promise<ServerState | null> {
  try {
    const res = await fetch("/api/progress");
    if (!res.ok) return null;
    const data = (await res.json()) as { chapters?: unknown; seen?: unknown };
    if (!data.chapters || typeof data.chapters !== "object") return null;
    const chapters: Record<string, Status> = {};
    for (const [id, s] of Object.entries(data.chapters)) {
      if (isStatus(s)) chapters[id] = s;
    }
    const seen = Array.isArray(data.seen) ? data.seen.filter((x) => typeof x === "string") : [];
    return { chapters, seen };
  } catch {
    return null;
  }
}

// Asked once, then kept. Cleared again if the server ever says 401.
function askForKey(): string | null {
  const stored = localStorage.getItem(KEY_KEY);
  if (stored) return stored;
  const typed = window.prompt("Workbook key (William has it):")?.trim() ?? "";
  if (typed) localStorage.setItem(KEY_KEY, typed);
  return typed || null;
}

// PUT with the key in a header. False means nothing changed on the server,
// and the caller puts the checkbox back the way it was.
async function put(path: string, body: unknown): Promise<boolean> {
  const key = askForKey();
  if (!key) return false;
  try {
    const res = await fetch(path, {
      method: "PUT",
      headers: { "Content-Type": "application/json", "X-Workbook-Key": key },
      body: JSON.stringify(body),
    });
    if (res.status === 401) {
      localStorage.removeItem(KEY_KEY);
      window.alert("The server refused that key. Ask William for the current one.");
    }
    return res.ok;
  } catch {
    return false;
  }
}

function make<K extends keyof HTMLElementTagNameMap>(
  tag: K,
  className = "",
  text = "",
): HTMLElementTagNameMap[K] {
  const node = document.createElement(tag);
  if (className) node.className = className;
  if (text) node.textContent = text;
  return node;
}

function renderChapters(list: HTMLOListElement, state: ServerState | null): void {
  const status: Record<string, Status> = {};
  for (const id of CHAPTER_IDS) status[id] = state?.chapters[id] ?? "todo";

  const bar = make("div", "bar");
  const fill = make("div", "bar-fill");
  bar.append(fill);
  const paint = () => {
    fill.style.width = `${Math.round((100 * countDone(status)) / CHAPTERS.length)}%`;
  };

  for (const c of CHAPTERS) {
    const id = chapterId(c);
    const li = make("li");
    li.dataset.chapter = id;
    li.dataset.status = status[id];
    const box = make("input");
    box.type = "checkbox";
    box.checked = status[id] === "done";
    box.addEventListener("change", async () => {
      const next: Status = box.checked ? "done" : "todo";
      if (!(await put(`/api/progress/${id}`, { status: next }))) {
        box.checked = !box.checked;
        return;
      }
      status[id] = next;
      li.dataset.status = next;
      paint();
    });
    const link = make("a", "", c.title);
    link.href = `chapters/${c.slug}.html`;
    const meta = make("span", "meta");
    meta.append(make("span", "badge", c.mechanic), make("span", "", c.time));
    li.append(make("span", "num", String(c.number)), box, link, meta);
    list.append(li);
  }
  list.after(bar);
  paint();
}

function renderLibrary(state: ServerState | null): void {
  for (const item of libraryData.items) {
    if (!isCategory(item.category)) continue;
    const list = document.querySelector<HTMLUListElement>(`ul[data-category="${item.category}"]`);
    if (!list) continue;
    const li = make("li");
    li.dataset.added = item.added;
    li.dataset.seen = item.seen || state?.seen.includes(item.id) ? "yes" : "no";
    const box = make("input");
    box.type = "checkbox";
    box.title = "seen";
    box.checked = li.dataset.seen === "yes";
    box.addEventListener("change", async () => {
      if (!(await put(`/api/seen/${item.id}`, { seen: box.checked }))) {
        box.checked = !box.checked;
        return;
      }
      li.dataset.seen = box.checked ? "yes" : "no";
    });
    const link = make("a", "", item.title);
    link.href = item.url;
    li.append(box, " ", link, " ", make("span", "why", item.why));
    list.append(li);
  }
}

async function main(): Promise<void> {
  const state = await loadState();
  if (!state) console.warn("No /api/progress here. Run npm run dev:full to talk to the database.");
  const chapterList = document.querySelector<HTMLOListElement>("ol#chapters");
  if (chapterList) renderChapters(chapterList, state);
  if (document.querySelector("ul[data-category]")) renderLibrary(state);
}

What can go wrong

  • The AI offers to "make the key not prompt every time" and writes it into main.ts. This is the chapter's planted moment. main.ts is shipped to every visitor's browser; a key in it is a key on the internet. Reject the diff, and read rule 7 in AGENTS.md aloud to it if you like. The prompt-once-and-store behaviour it dislikes is the design.
  • Ticks work on your laptop but the live site says {"error":"unauthorized"}. Read the story. Your browser holds the local key from .dev.vars; the live site wants William's. The page clears the stored key on a 401 and asks again; paste the right one. If it says WORKBOOK_KEY is not set on the server (a 500, not a 401), the secret has not been set in the dashboard yet.
  • Live site: "no such table" or an empty scoreboard. The migration ran with --local only. Run it with --remote. The reverse (works live, empty on the laptop) is the same mistake the other way round.
  • The Function fails on Cloudflare with something about DB being undefined. The [[d1_databases]] block is missing or the id is wrong, or it was added to the dashboard instead of the file. Once wrangler.toml has pages_build_output_dir, dashboard bindings are ignored; the block must be in the file, in the same commit as the Functions.
  • wrangler login hangs. No browser could open: you are in a terminal inside an AI chat, or over a remote connection. Use the plain Cursor terminal or Windows Terminal, or copy the printed URL.
  • npm run dev:full shows the old site. It serves dist, which is whatever the last build wrote. The script builds first; if you ran npx wrangler pages dev dist by hand, build first.
  • Ticks do not stick on npm run dev. Correct: that is Vite alone, with no Functions and no database. The console says so. dev:full is the one with the server.
  • The PUT returns 400. The body was not JSON, or status was not one of the two words. The error text says which. Every branch in the Function returns a sentence for a reason.
  • The AI adds CORS headers "to fix the fetch". Ask it what CORS is for: browsers refusing to let one site read another site's API. Your page and your API are the same site, so there is nothing to fix. Reject.
  • Nothing in the deployment log explains a failing request. Function logs are separate: npx wrangler pages deployment tail streams them live while you click. Add a console.log in the Function if you need to see a value.
  • tsc -p functions complains that Response or fetch has two definitions. functions/tsconfig.json lost its lib line, so the browser's DOM types and Cloudflare's are both loaded. Restore it.

Deliberately not in this chapter

No accounts, no login page, no passwords: one shared key is the smallest thing that works for one writer. No library that wraps SQL (an "ORM"): three sentences of SQL are easier to read than the library that would hide them. No caching, no rate limit, no middleware. No way to read the seen table on its own: it rides along with /api/progress. Each of these has a chapter of its own in some other book.
