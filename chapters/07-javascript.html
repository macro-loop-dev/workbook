JavaScript makes it interactive

The page can change itself. The browser can remember. And remembering on one device is not the same as sharing.

Why this chapter exists

So far every change to the site has been a change to a file, made by you, in Cursor. JavaScript is the language browsers run, and it lets a page change itself after it has loaded: add a checkbox, react to a click, remember the click for next time. Today you write a small program that does exactly that, and you find out where the browser keeps what it remembers.

The catch is the last line of the lede. What this browser remembers stays in this browser; your phone will not know. Chapters 8 and 9 fix that properly. This chapter exists so you feel the problem first.

A story

FloatNote's CLAUDE.md, August 2026

FloatNote saves its settings in a folder under AppData. To test that, William started the app from inside another program, the Claude desktop app. The app said the settings were saved. The file was not in the folder. Windows had quietly redirected the writes somewhere else, because of how that other program is packaged, and nothing told anyone. The rule he wrote down afterwards has a short general version: "saved" always means "saved somewhere", and the somewhere is a question worth asking. Step 10 asks it of your browser.

What you will do

  • Make a file the browser runs, and prove that where it is loaded matters.
  • Use the console, the Elements tab and one breakpoint as tools.
  • Write the counting function yourself; let the AI write the remembering part; review it.
  • Add five CSS rules, all from existing tokens.
  • Find your ticks on your disk, then find that your phone cannot see them.

Do it

  1. A file the browser runs. In Cursor, at the top level of the repo next to index.html, make a new file script.js containing one line: 
    console.log("hello from script.js");
    In index.html, add this as the last line inside <body>, just above </body>: 
    <script src="script.js"></script>
    Save both. Refresh the browser, press F12, click Console.

    hello from script.js. F12 opens DevTools, the browser's toolbox. The console is where a page talks to you and where errors appear. The tag means "run this file, here, now".

  2. Prove that "here" matters. Add a second line: 
    console.log(document.querySelector(".chapters"));
    Refresh: the console prints the <ol>, and hovering it lights up the list. Now cut the <script> tag and paste it inside <head>. Refresh.

    null. The browser reads the file top to bottom and ran your script before the list existed. Put the tag back at the end of <body>. Every "cannot read properties of null" you will ever see is a version of this.

  3. Change the page without changing the file. DevTools, Elements tab. Press Ctrl+Shift+C, click chapter 7 in the list: its <li> is highlighted with data-status="todo". Double-click todo, type done, Enter.

    The box fills, the counter says 8, and index.html did not change. Refresh: back to 7. That is what your script will do, and then remember.

  5. Let the AI write the remembering part, then review it. In Cursor chat, with script.js open: 
    Add two functions to script.js. load(key) returns the object stored in
localStorage under key, or {} if there is nothing there or it is not valid

  6. Type the rest. This is the complete file, as it should read when you are finished. Yours may differ in small ways as long as it does the same things. 
    // script.js, from chapter 7. Loaded by a <script> tag at the very end of
// <body> on index.html and library/index.html, so everything it looks for
// already exists when it runs.
//
// It does three things: puts a checkbox on every chapter and every Library
// item, remembers your ticks in this browser, and draws a progress bar.
// The data-status and data-seen attributes stay the truth for CSS; this
// script reads them, lets you change them, and writes them back.

const PROGRESS_KEY = "workbook.progress.v1";
const SEEN_KEY = "workbook.seen.v1";

// ---- remembering ----------------------------------------------------------
// localStorage stores strings only, so objects go in and out as JSON text.

function load(key) {
  try {
    const text = localStorage.getItem(key);
    const value = text ? JSON.parse(text) : {};
    return value && typeof value === "object" ? value : {};
  } catch (error) {
    console.warn("Could not read " + key, error);
    return {};
  }
}

function save(key, value) {
  try {
    localStorage.setItem(key, JSON.stringify(value));
  } catch (error) {
    console.warn("Could not save " + key, error);
  }
}

// ---- one checkbox, at the start of a list item ----------------------------

function addCheckbox(li, checked, onChange) {
  const box = document.createElement("input");
  box.type = "checkbox";
  box.checked = checked;
  box.title = "Remembered by this browser only";
  box.addEventListener("change", function () {
    onChange(box.checked);
  });
  li.prepend(box);
  return box;
}

// ---- the chapter list (index.html) ----------------------------------------

function countDone(items) {
  let done = 0;
  for (const li of items) {
    if (li.dataset.status === "done") {
      done = done + 1;
    }
  }
  return done;
}

function drawBar(fill, items) {
  const percent = items.length === 0 ? 0 : Math.round((countDone(items) / items.length) * 100);
  fill.style.width = percent + "%";
}

function setUpChapters() {
  const list = document.querySelector(".chapters");
  if (!list) {
    return; // not this page
  }
  const items = list.querySelectorAll("li[data-chapter]");
  const saved = load(PROGRESS_KEY);

  const bar = document.createElement("div");
  bar.className = "bar";
  const fill = document.createElement("div");
  fill.className = "bar-fill";
  bar.append(fill);
  list.after(bar);

  for (const li of items) {
    const id = li.dataset.chapter;
    const remembered = saved[id];
    if (remembered === "done" || remembered === "todo") {
      li.dataset.status = remembered; // this browser's note beats the file
    }
    addCheckbox(li, li.dataset.status === "done", function (ticked) {
      li.dataset.status = ticked ? "done" : "todo";
      saved[id] = li.dataset.status;
      save(PROGRESS_KEY, saved);
      drawBar(fill, items);
    });
  }
  drawBar(fill, items);
}

// ---- the Library (library/index.html) -------------------------------------

function setUpLibrary() {
  const items = document.querySelectorAll(".library li[data-seen]");
  if (items.length === 0) {
    return; // not this page
  }
  const saved = load(SEEN_KEY);

  for (const li of items) {
    const link = li.querySelector("a");
    if (!link) {
      continue;
    }
    const id = link.getAttribute("href"); // the address is the item's name
    const remembered = saved[id];
    if (remembered === "yes" || remembered === "no") {
      li.dataset.seen = remembered;
    }
    addCheckbox(li, li.dataset.seen === "yes", function (ticked) {
      li.dataset.seen = ticked ? "yes" : "no";
      saved[id] = li.dataset.seen;
      save(SEEN_KEY, saved);
    });
  }
}

setUpChapters();
setUpLibrary();
    The new words: document.createElement makes an element that is not on the page yet; li.prepend puts it at the start of the item; addEventListener("change", ...) means "when this changes, run this"; list.after(bar) puts the bar under the list; fill.style.width is the one place this site sets a style from code, because the width is a number JavaScript works out. Refresh.

    Checkboxes at the start of every chapter line, badly placed for now, and a thin empty strip under the counter. No red in the console. If there is red, read it: it names the line.

  7. Five CSS rules. Add this at the very end of styles.css. Every colour and size is an existing token. 
    /* ---- chapter 7: checkboxes and the progress bar --------------------------- */
.chapters li:has(> input[type="checkbox"])::before { display: none; }
.chapters li > input[type="checkbox"] { margin: 0; accent-color: var(--done); }
.library li > input[type="checkbox"] { margin: 0 var(--sp-2) 0 0; accent-color: var(--done); }
.bar {
  height: var(--sp-2);
  margin-top: var(--sp-4);
  border: 1px solid var(--border);
  border-radius: var(--radius-pill);
  background: var(--field);
  overflow: hidden;
}
.bar-fill {
  height: 100%;
  width: 0;
  background: var(--accent);
  border-radius: var(--radius-pill);
}
    The first rule hides the CSS-drawn box only when a checkbox is present, so if the script ever fails the box comes back. The next two tidy the checkbox and give it the "done" colour. The last two are the bar and its filling. Refresh.

    A checkbox where each box was, seven ticked, and a bar 58% full under "7 of 12 done". Tick chapter 7: the bar grows, the counter says 8. Refresh: still 8. The browser remembered.

  8. The Library too. In library/index.html, the same tag just above </body>, except the file is one folder up: 
    <script src="../script.js"></script>

    Refresh the Library: a checkbox before every item. Tick one: its new badge goes and the count drops. Refresh: it stays. Nothing appeared twice on either page, because the script checks which page it is on before doing anything.

  9. One breakpoint. DevTools, Sources tab, click script.js in the left list. Find saved[id] = li.dataset.status; inside setUpChapters and click its line number; it turns blue. Tick a chapter.

    The page freezes on that line. A breakpoint is a "stop here" mark. Hover over saved to see the object being remembered, and over id. F8 continues. Click the number again to remove it. This beats console.log as soon as a program does more than one thing.

  10. Where is it kept? DevTools, Application tab, Local Storage on the left, the file:// entry.

    Two names, workbook.progress.v1 and workbook.seen.v1, each holding JSON text. Right-click one, delete it, refresh: those ticks are gone. And "there" is a real folder. In PowerShell 7, for Edge (for Chrome, swap Microsoft\Edge for Google\Chrome):

    Get-ChildItem "$env:LOCALAPPDATA\Microsoft\Edge\User Data\Default\Local Storage\leveldb"

    A handful of files with odd names: the browser's own small database, your ticks in it next to every other site's drawer. Not readable by eye, but on your disk, in your user folder, and nowhere else.

What can go wrong

  • The AI suggests type="module", import, or fetch("progress.json"). All three are dead on a page opened from a file: browsers refuse to load modules or fetch over file:// for safety. The page would work on the live site and break on your laptop, the worst kind of bug. Chapter 8 brings a real server; then modules are allowed.
  • "Uncaught TypeError: Cannot read properties of null". A selector found nothing: a misspelled class, or the script ran before the page existed (step 2). Check the tag is last in <body>, then check the spelling against the Elements tab.
  • Nothing happens and no error. The script did not load. The Network tab shows it in red. The path is script.js from index.html and ../script.js from the Library.
  • Ticks vanish on refresh and the Application tab is empty. A private window, a browser set to clear site data on close, or one that blocks storage on file://. Use Edge or Chrome, normal window.
  • Every page opened from a file shares one drawer. The browser keeps one localStorage for all file:// pages, so another project saving under the name progress would collide with this one. Hence workbook. at the front, and .v1 at the end so a later chapter can change the shape without misreading old data.
  • Works on the live site but not from the file, or the other way round. Always check both. They are different origins (chapter 5's story) with different drawers; ticks on one do not appear on the other, and that is correct.
  • The AI rewrites the whole file when you ask for one function. Reject. Ask again naming the function and saying "change nothing else".
  • Checkboxes appear but the drawn boxes are still there. The first CSS rule is missing or misspelled.

Deliberately not in this chapter

No framework and no library: the whole program is one file you can read in five minutes. No fetch and no server: the phone disagreeing with the laptop is the lesson, and chapter 9 fixes it properly. No TypeScript until chapter 8. Five CSS rules and not one more; the bar does not animate.
