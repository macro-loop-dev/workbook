Chapter 8mechanic: build + tests4-6 hours, in two halves

A build step

Tools that check your work before a human does. From now on a program reads your files before the browser does, and four commands have to agree with you before anything ships.

Why this chapter exists

Until now the browser read your files straight off the disk. That was the point of chapter 1, and it is still true underneath. But a real project has more files than a person can hold in their head, and mistakes that a human reviewer will not spot: a misspelled key, a link to a page that was renamed, a function called with the wrong kind of value. This chapter adds four programs that look for exactly those things, and a fifth that runs them on a machine that is not yours every time you push.

The words, once, so the rest of the chapter can use them. A build is a program that reads your source files and writes the files the website actually serves, into a folder called dist. npm is the tool that downloads other people's code (packages) and runs your named commands. TypeScript is JavaScript with types: you say what kind of thing each value is, and a checker refuses to build if you break your own promises. A linter reads code for mistakes and style without running it; ours is called Biome. A test is a small program whose only job is to run your code and complain if the answer is wrong. CI you met in chapter 4: the copy of all this that runs on GitHub's computers and cannot be skipped.

Every one of these is the exact tool FloatNote uses, chosen so that chapter 11 feels like a place you have been. There is one more reason to do it now: the file-double-click era ends today. From this chapter the site is served by a small program, which is what lets chapter 9 talk to a server.

A story

FloatNote, src/docs.test.ts, 2026-08-24

The top of one of FloatNote's test files reads, word for word:

Content-rot guard for the /docs chapters, the sibling of tutorial.test.ts.

The docs page opens with "every example below runs through the real calculator, live" — so an example that silently stops computing makes the page lie. This nearly shipped once: the crypto examples were added to the money chapter while the docs page fetched only ECB rates, so they rendered blank.

The other half is the reverse risk. Chapters are a real FloatNote document, so an UNQUOTED @-tag line in a chapter would fire a live API request in every reader's browser on page load. Tag examples must stay backtick-quoted; this pins that.

You met the first half of that story in chapter 1. What is new is the second sentence: the page lied once, so now a program reads every example on every push and refuses to let it lie again. A test is a story about a mistake, written down so precisely that a computer can check it did not come back. Every test you write today is that shape.

What you will do

  • 8a, tools. Turn the folder into an npm package. Install Vite, TypeScript, Biome, tsx and marked. Move script.js into src/main.ts with types. Move the chapter list and the Library into small data files that the script draws from. Turn your notes into Markdown that the build renders to pages. See the site on localhost:5173 and build it into dist.
  • Mid-checkpoint with William.
  • 8b, tests. Write four small test scripts in the same shape FloatNote uses. Add a checks job to CI so they run on every push. Mark the chapter done by changing one key in a JSON file, with every check green.

Read the whole chapter once before typing anything. It is long because every file you create is printed in full; nothing here is a sketch.

  8. Create vite.config.ts. This tells Vite two things it cannot guess: which pages exist (it bundles nothing it is not told about), and how to turn your Markdown notes into pages. The second part is a small plugin: a function that returns an object with named hooks Vite calls at the right moments. configureServer runs while you work; generateBundle runs during a build. 
    import { readdirSync, readFileSync } from "node:fs";
import { marked } from "marked";
import { defineConfig, type Plugin } from "vite";

// Vite bundles only the pages it is told about. Every chapter is a page.
const pages: Record<string, string> = { index: "index.html", library: "library/index.html" };
for (const f of readdirSync("chapters")) {
  if (f.endsWith(".html")) pages[f.slice(0, -5)] = `chapters/${f}`;
}

// ---- notes: Markdown in, pages out --------------------------------------
// notes/*.md become notes/*.html, on the dev server and in dist. A file whose
// name starts with _ is a template and is skipped.
interface Note {
  name: string;
  title: string;
  date: string;
  body: string;
}

function readNotes(): Note[] {
  return readdirSync("notes")
    .filter((f) => f.endsWith(".md") && !f.startsWith("_"))
    .map((f) => {
      const name = f.slice(0, -3);
      const raw = readFileSync(`notes/${f}`, "utf8");
      const m = /^---\r?\n([\s\S]*?)\r?\n---\r?\n?([\s\S]*)$/.exec(raw);
      const head: Record<string, string> = {};
      for (const line of (m?.[1] ?? "").split(/\r?\n/)) {
        const i = line.indexOf(":");
        if (i > 0) head[line.slice(0, i).trim()] = line.slice(i + 1).trim();
      }
      return { name, title: head.title ?? name, date: head.date ?? "", body: m?.[2] ?? raw };
    })
    .sort((a, b) => b.date.localeCompare(a.date) || a.name.localeCompare(b.name));
}

const esc = (s: string) => s.replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;");

function page(title: string, main: string): string {
  return `<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>${esc(title)} · Notes</title>
<link rel="stylesheet" href="../styles.css">
</head>
<body>
<div class="page">
  <nav class="site-nav" aria-label="Site">
    <a class="brand" href="../index.html">The Workbook</a>
    <a href="../index.html">Chapters</a>
    <a href="../library/index.html">Library</a>
    <a href="index.html" aria-current="page">Notes</a>
  </nav>
${main}
  <nav class="pager"><a href="index.html">&larr; all notes</a></nav>
</div>
</body>
</html>
`;
}

function renderNote(n: Note): string {
  const header = `  <header class="chapter-header"><div class="kicker"><span>${esc(n.date)}</span></div><h1>${esc(n.title)}</h1></header>\n`;
  return page(n.title, header + marked.parse(n.body, { async: false }));
}

function renderIndex(notes: Note[]): string {
  const items = notes
    .map(
      (n) =>
        `    <li><span class="date">${esc(n.date)}</span><a href="${n.name}.html">${esc(n.title)}</a></li>`,
    )
    .join("\n");
  return page(
    "Notes",
    `  <h1>Notes</h1>\n  <p class="lede">Yours. Nobody edits these but you.</p>\n  <ul class="notes-list">\n${items}\n  </ul>\n`,
  );
}

function notesPlugin(): Plugin {
  const html = (name: string): string | null => {
    const notes = readNotes();
    if (name === "index") return renderIndex(notes);
    const n = notes.find((x) => x.name === name);
    return n ? renderNote(n) : null;
  };
  return {
    name: "workbook-notes",
    configureServer(server) {
      server.middlewares.use((req, res, next) => {
        const m = /^\/notes\/(?:([^/?]+)\.html)?(?:\?.*)?$/.exec(req.url ?? "");
        const out = m ? html(m[1] ?? "index") : null;
        if (out === null) return next();
        res.setHeader("Content-Type", "text/html; charset=utf-8");
        res.end(out);
      });
    },
    generateBundle() {
      for (const name of ["index", ...readNotes().map((n) => n.name)]) {
        this.emitFile({ type: "asset", fileName: `notes/${name}.html`, source: html(name) ?? "" });
      }
      // The notes pages link ../styles.css by name; Vite copies nothing it is
      // not told about, so tell it.
      this.emitFile({
        type: "asset",
        fileName: "styles.css",
        source: readFileSync("styles.css", "utf8"),
      });
    },
  };
}

export default defineConfig({
  appType: "mpa",
  plugins: [notesPlugin()],
  build: { rollupOptions: { input: pages } },
});

    It is the longest file in the chapter. Read readNotes slowly: it reads the folder, splits each file into the front matter (the block between the two --- lines, holding a title and a date) and the body, and sorts by date. The rest is a page template around what marked produces.

    // The page's only script. Draws the chapter list and the Library from the
// files in src/, then layers on what this browser remembers (chapter 7).
import { CHAPTERS, chapterId } from "./chapters";
import { isCategory } from "./library";
import libraryData from "./library.json";
import { countDone, isStatus, type Status } from "./progress";
import progressData from "./progress.json";

// Same two keys as chapter 7. The prefix matters: every page you ever open
// on this computer's localhost shares one localStorage.
const PROGRESS_KEY = "workbook.progress.v1";
const SEEN_KEY = "workbook.seen.v1";

function readOverlay(key: string): Record<string, string> {
  try {
    const parsed: unknown = JSON.parse(localStorage.getItem(key) ?? "{}");
    if (parsed && typeof parsed === "object" && !Array.isArray(parsed)) {
      return parsed as Record<string, string>;
    }
  } catch {
    // not JSON: it is a cache, not the truth, so start again
  }
  return {};
}

function writeOverlay(key: string, value: Record<string, string>): void {
  localStorage.setItem(key, JSON.stringify(value));
}

function make<K extends keyof HTMLElementTagNameMap>(
  tag: K,
  className = "",
  text = "",
): HTMLElementTagNameMap[K] {
  const node = document.createElement(tag);
  if (className) node.className = className;
  if (text) node.textContent = text;
  return node;
}

function renderChapters(list: HTMLOListElement): void {
  const committed: Record<string, string> = progressData.chapters;
  const overlay = readOverlay(PROGRESS_KEY);
  const status: Record<string, Status> = {};
  for (const c of CHAPTERS) {
    const id = chapterId(c);
    const s = overlay[id] ?? committed[id];
    status[id] = isStatus(s) ? s : "todo";
  }

  const bar = make("div", "bar");
  const fill = make("div", "bar-fill");
  bar.append(fill);
  const paint = () => {
    fill.style.width = `${Math.round((100 * countDone(status)) / CHAPTERS.length)}%`;
  };

  for (const c of CHAPTERS) {
    const id = chapterId(c);
    const li = make("li");
    li.dataset.chapter = id;
    li.dataset.status = status[id];
    const box = make("input");
    box.type = "checkbox";
    box.checked = status[id] === "done";
    box.addEventListener("change", () => {
      status[id] = box.checked ? "done" : "todo";
      li.dataset.status = status[id];
      overlay[id] = status[id];
      writeOverlay(PROGRESS_KEY, overlay);
      paint();
    });
    const link = make("a", "", c.title);
    link.href = `chapters/${c.slug}.html`;
    const meta = make("span", "meta");
    meta.append(make("span", "badge", c.mechanic), make("span", "", c.time));
    li.append(make("span", "num", String(c.number)), box, link, meta);
    list.append(li);
  }
  list.after(bar);
  paint();
}

function renderLibrary(): void {
  const overlay = readOverlay(SEEN_KEY);

  1. Create src/progress.test.ts. The shape is FloatNote's: two counters, a small eq helper that compares what you got with what you wanted, a list of checks, and at the end an exit code of 1 if anything failed. That exit code is what CI reads. 
    // progress.json is data, and data rots: a typo in a status would silently

import { CHAPTER_IDS, countDone, isChapterId, isStatus } from "./progress";
import data from "./progress.json";

let pass = 0;
let fail = 0;
function eq(name: string, actual: unknown, expected: unknown) {
  if (JSON.stringify(actual) === JSON.stringify(expected)) {
    pass++;
  } else {
    fail++;
    console.log(`FAIL: ${name}: got ${JSON.stringify(actual)}, want ${JSON.stringify(expected)}`);
  }
}

eq("one entry per chapter, no extras", Object.keys(data.chapters).sort(), [...CHAPTER_IDS]);

  eq(`chapter ${id} has a real status`, isStatus(status), true);

What can go wrong

  • "npm.ps1 cannot be loaded because running scripts is disabled". You are in the blue Windows PowerShell, or chapter 0's execution-policy step was skipped. Check the terminal icon; check $PSVersionTable.PSVersion starts with 7.
  • CI fails at npm ci with "package-lock.json not found" or "lock file out of sync". The lock was not committed, or you edited package.json by hand after installing. Run npm install once (it fixes the lock), commit the lock, push.
  • Biome lists errors, not just formatting. Each one names a rule. Read the rule name and the sentence under it; most are one-line fixes ("do not shadow the global escape" means: pick another name). lint:fix only fixes the safe ones.
  • A chapter page is missing from dist. Vite bundled only what pages in vite.config.ts named. That object is built by reading the chapters folder, so the usual cause is a file that does not end in .html, or a chapter saved somewhere else. Adding an entry by hand is the wrong fix; find why the loop missed it.
  • Cloudflare's build fails with a Node error, or "vite: not found", before your code runs. It used Node 18. .node-version fixes it; William also sets NODE_VERSION=22 in the dashboard at the checkpoint, and switches the build command to npm run build and the output folder to dist. Until he does, a merge would deploy the old static site.
  • tsx says it cannot find ./progress.json, or TypeScript complains about importing JSON. resolveJsonModule is missing from tsconfig.json. It is in the file above; check for a typo.
  • import.meta.dirname is undefined. Node is older than 20.11. node --version should say 22; if not, chapter 0's installer picked something else, and William can help.
  • Notes look unstyled on the built site but fine in dev. The generated note pages link ../styles.css by name, and Vite copies nothing it is not told about. The plugin's last emitFile line copies it; if you trimmed that line, put it back. Chapter pages never had the problem because they are entries, and Vite rewrote their stylesheet link itself.
  • The AI suggests Jest, Vitest, ESLint or Prettier. Say no. They are fine tools; they are not the ones FloatNote uses, and learning two of everything is the wrong trade at this point. The AI also has to ask before any install (rule 5 in AGENTS.md); if it did not ask, that is the diff to reject.
  • Port 5173 is already in use. A dev server from another terminal is still running. Vite picks 5174 and prints it; read the terminal rather than the chapter.
  • Double-clicking index.html shows no chapters. Correct. That page needs the server now. npm run dev.
