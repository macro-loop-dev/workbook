Set up the machine

Six installs, four settings, two accounts. Nothing here is hard, and every bit of it will bite later if it is skipped.

Why this chapter exists

Every chapter after this one assumes six tools exist and answer when called. Doing them one at a time, out loud, in a terminal, is also your first lesson: a command is a sentence you type, and the computer replies. You will type hundreds of them; these are the first six.

The accounts matter more than the tools. Tools can be reinstalled. A GitHub account is where all of your work will live, and you will want the same one at 25.

A story

William's laptop, 2026-08-22

William ran a setup script that was supposed to link some config files, so that updating one place would update everywhere. It printed success. Days later nothing was updating. The script had silently made copies instead of links, because he had run it in the old blue "Windows PowerShell" instead of the new black "PowerShell 7". Same commands, same screen, different program. Which terminal you are in is a real variable, and this chapter makes sure it is the right one.

What you will do

  • Make two accounts: GitHub and Cursor.
  • Install PowerShell 7, Git, the GitHub CLI, Node, gitleaks and Cursor with six commands.
  • Set four git settings and one PowerShell setting.
  • Log in to GitHub from the terminal.
  • Point Cursor's terminal at PowerShell 7.

Do it

  1. GitHub account. Go to github.com/signup. Use your personal email, not a school one: schools change, this account should not. Pick a username you would be happy to see on a job application. Turn on two-factor authentication with an authenticator app on your phone, download the recovery codes, and print them or write them somewhere physical.

    Done when: you can log in on your phone with the app code.

  2. Cursor account. Go to cursor.com and sign up with the same personal email. William will check whether a student plan is available; if not, the free tier is enough for chapters 1 to 7.
  3. Open a terminal. Press the Windows key, type terminal, open Terminal. The tab will say "Windows PowerShell". That is the old one; fine for the next step only.
  4. Install the six tools. Paste these one at a time. Each one prints a progress bar, then "Successfully installed". Some pop up an installer window; accept the defaults. 
    winget install --id Microsoft.PowerShell -e
winget install --id Git.Git -e
winget install --id GitHub.cli -e
winget install --id OpenJS.NodeJS.22 -e
winget install --id Gitleaks.Gitleaks -e
winget install --id Anysphere.Cursor -e

    If winget itself is "not recognized", install "App Installer" from the Microsoft Store and reopen the terminal.

  5. Close the terminal completely and open PowerShell 7. Windows key, type pwsh, open PowerShell 7. Black icon. From now on, always this one. In Terminal you can make it the default: Settings → Startup → Default profile → PowerShell.

    $PSVersionTable.PSVersion prints a version starting with 7.

  6. Allow scripts to run. Node's tools are PowerShell scripts, and Windows blocks those by default. 
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

    Answer Y. No output means it worked.

  7. Tell git who you are and how to behave. Use the same name and email as your GitHub account. 
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global core.autocrlf false
git config --global pull.ff only
git config --global init.defaultBranch main

    The last three prevent three different confusing messages you would otherwise meet in chapters 3, 5 and 4. You do not need to understand them yet.

  8. Log in to GitHub from the terminal. 
    gh auth login
    Answer: GitHub.com, HTTPS, Yes (authenticate git), Login with a web browser. Copy the code it shows, press Enter, paste the code in the browser.

    gh auth status says "Logged in to github.com".

  9. Open Cursor and sign in. Then Settings (the gear, top right) → search "default profile" → Terminal › Integrated › Default Profile: Windows → PowerShell. Not "Windows PowerShell". Same trap as the story.

Check

In PowerShell 7, paste this whole block. Every line should print a version or a status, none should say "not recognized".

git --version
gh auth status
node --version
npm --version
gitleaks version
cursor --version

What can go wrong

  • "not recognized as the name of a cmdlet". Almost always: the tool was installed but this terminal was opened before that. Close the terminal completely and open a new one. This is the number one cause of "it doesn't work" for the rest of the course.
  • "npm.ps1 cannot be loaded because running scripts is disabled". You are in the blue Windows PowerShell, or step 6 was skipped. Open PowerShell 7 and check $PSVersionTable.PSVersion.
  • gh auth login asks about SSH keys. You arrowed onto SSH instead of HTTPS. Ctrl+C and start again; choose HTTPS.
  • winget says the package was not found. The ids above were checked on 2026-09-03. Search with winget search cursor and tell William if the id has changed.
  • Two-factor codes stop working. This is what the recovery codes are for. That is why they are on paper.
